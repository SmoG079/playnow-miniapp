# 小程序支付开关统一（2026-10-19）

## 原因与行为

订场支付使用 `WX_PAY_ENABLED`，赛事仍使用独立且默认关闭的开关。线上统一支付值已经为 true，但没有配置赛事独立值，导致收费 1 元的比赛仍返回 `prepay_enabled=false`，前端禁用报名按钮，后端也拒绝付费报名。

删除赛事专用配置项，订场和赛事新付款统一读取 `WX_PAY_ENABLED`，不保留旧开关别名或回退逻辑。赛事详情中的能力字段 `prepay_enabled` 直接映射统一开关，无须更新现有客户端即可读取正确状态。

- true：订场走真实微信预支付；赛事付费报名及微信预支付开放。
- false：赛事付费报名及新付款拒绝；订场保留原有本地/CI 占位契约，不产生真实交易。
- 免费赛事不受付款开关影响。
- 关闭新付款不阻断已付款交易的回调、查单、关单和退款恢复。自动分账仍由原独立开关管理，不属于收款开关。

同步更新配置示例、启动日志和赛事说明。线上配置只读核查确认原赛事开关没有出现在生产环境文件，无需修改商户凭据或新增环境变量。没有数据库结构或业务数据变更。

## 验证

隔离 SQLite 后端回归 428 项通过、1 项因专用 MySQL 环境缺失跳过、10 项既有历史支付测试按项目 CI 范围排除；独立查询、HTTP 路由及计价 17 项单元测试通过。

新增统一开关用例验证：详情能力字段、付费报名、真实预支付参数和再次关闭后的拦截；免费报名始终正常。使用模拟微信客户端验证 1 元转换为 100 分，返回客户端支付参数。已有回调退款用例增加关闭统一开关后继续处理重复回调和退款的覆盖。全流程模拟测试不等同于真实商户资金链路验收。

发布后只读核对正式版本、服务健康、统一开关、比赛详情能力字段和小程序按钮。不会代替用户创建报名或发起真实付款。
