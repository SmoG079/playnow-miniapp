# 需求文档

## 1. 项目概述

- **产品定位**：面向网球俱乐部（羽毛球、篮球、足球等）的微信小程序平台
- **核心功能**：俱乐部发布场地信息和时间表，用户在线预约并支付，平台通过微信分账 API 与俱乐部结算，提供约球社交和比赛报名功能
- **设计原则**：俱乐部和用户使用同一个小程序，通过角色权限控制功能可见性，无独立 Web 管理后台

| 编号 | 需求 | 优先级 |

| B-03 | 下单后锁场 10 分钟，超时未支付自动释放（Redis SET NX EX + DB 兜底） | P0 |

| B-08 | 包场/拼场模式（P2 扩展） | P2 |

## 5. 支付 & 分账（模块 P）P1

| 编号 | 需求 | 优先级 |
|------|------|--------|
| P-01 | 用户支付 → 平台商户号（资金归集） | P0 |
| P-02 | 通过微信分账 API 按比例分账到俱乐部子商户号 | P0 |
| P-03 | 分账比例按俱乐部维度可配置（默认平台抽 10%） | P1 |
| P-04 | 分账记录：每笔订单可查分账状态、金额、时间 | P0 |

**分账模型**：用户支付 → 平台商户号 → 30 天后微信分账 API → 平台得 10% + 俱乐部得 90%

## 9. UI 结构 & 权限设计

**底部 TabBar（5 项）**：

- **Tab 0：首页** - 约球帖 feed、比赛推荐、搜索、分享、拉群入口
- **Tab 1：订场** - 俱乐部列表、场地预约、场地管理入口（仅管理员）
- **Tab 2：+ 发布中心** - 按角色动态显示：发布约球帖、创建俱乐部、发布比赛、管理场地、管理订单
- **Tab 3：消息** - 客服消息、群聊列表、系统通知
- **Tab 4：我的** - 普通用户：个人信息、预约、报名、约球帖、钱包；管理员额外：俱乐部管理、订单、分账、统计

### 设计决策
- **网球专属**：前端所有运动类型已移除，后端字段保留通用
- **30 分钟切分**：最小单位 30min，1 小时起订 = 连续 2 格
- **营业时间**：场地级别 `open_time`/`close_time`，创建时自动切分 3 天
- **支付占位**：`/bookings/{id}/pay` 直接标记成功，微信 V3 待接入
- **锁超时**：Redis 10 分钟 TTL + 查询时自动检测释放
