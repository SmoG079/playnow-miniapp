## 价格

场地 `price_rules` JSON 数组顺序即优先级，新规则默认置顶。支持 `date_range`、`weekly`、`monthly`、`daily_time`，保留旧 `time_range`；可组合有效日期、星期（1–7）、每月日期（1–31）和时间条件，全部满足才命中。日期闭区间，时段左闭右开，按上海时间和30分钟边界处理。月末不存在的日期不命中，不支持跨午夜时段。

价格预览为只读 POST：已有场地 `/venues/{id}/prices/preview`，新增场地 `/venues/with-club/{club_id}/prices/preview`。请求包含 `price_per_hour`、`price_rules`、`date`；响应逐时段返回小时价、时段金额和 `rule_index`（null表示基础价）。预览、订场展示和新订单使用相同计算服务。

独立时段 `price_override` 字段保留历史值，但不再参与报价；排期不再写入该字段，旧批量排期接口非空临时价格列表会被明确拒绝。未预订时段立即采用当前规则，已有订单金额不改。

Celery `expire_price_rules` 每分钟运行，有限日期规则在最后有效时段结束后删除。每个场地以数据库行锁保护，删除和管理员系统通知同事务提交，重复运行不会重复通知。无结束日期的每周、每月规则永久保留。

## 奖项与签表

- `prizes` 为可空 JSON 字段，Alembic 版本 `20261012_tournament_prizes`，前置为 `20261009_user_rating`。每条奖项包含 `name`（64字）及 `description`（2000字），最多20条；支持增删、排序、多行及草稿恢复。空列表隐藏详情分区；null兼容旧 `prize` 文本，明确清空不会恢复旧内容。
- `POST /tournaments/{id}/draw/adjust` 接收 `expected_version`、`idempotency_key`、`reason`、完整 `positions`（group_no、position、team_id）。所属俱乐部管理员和平台管理员有权限；无主办俱乐部仅平台管理员可用。普通创建者管理权限不授予手动调整权限。
- 单打个人、双打/混双整队交换，支持跨组但保持各组单位数；禁止重复、遗漏及双空首轮。循环赛按调整后的签位重建对阵；兼容从旧循环赛对阵还原实际签位顺序。
- 当前阶段无实际比分、胜负或弃权时可调整，自动轮空不算已比赛。保存新草稿版本，重新计算晋级和排场，发布前普通用户仍看到旧正式版本。赛事行锁、版本校验和幂等键保护并发，保留历史与审计。

## 赛事17接口错误

只读服务端日志及数据核查确认：`POST /tournaments/17/draw` 在2026-10-12返回409，当时对应赛事名单已冻结，目前只有1名符合抽签条件的单打选手，纯抽签校验返回「每组至少需要两队，请调整分组报名或补充参赛者」。人数校验继续保留。

管理详情返回 `draw_block_reason`，前端在条件不足时禁用抽签并展示原因；旧接口用符合条件的报名人数兜底。新增 `reopen-registration`，仅尚无签表、赛事开放且报名截止前允许管理者解除冻结、重新开放报名。

另一次只读 GET 日志显示 MySQL 2013连接丢失并导致500。连接池改为 `pool_pre_ping=True`、`pool_recycle=1800`，在连接取出前检测并定期回收，不对业务写入进行自动重试。隔离 MySQL 主动断开闲置池连接后，下一次查询成功更换连接。
