## 温度数据

新增公共只读接口 `GET /api/v1/discovery/weather?city=…&province=…`，使用已有 `TENCENT_MAP_KEY` / `TENCENT_MAP_SK`。先解析所选城市，再向腾讯位置服务查询实况天气，避免用手机所在城市的天气替代手动选择的城市。Key 与签名仅在后端使用。

接口按客户端 IP 限流，后端每进程按城市缓存 10 分钟（最多 256 项）；前端共享 15 分钟缓存及并发请求，失败后延迟 1 分钟再尝试，过期后在页面显示时刷新。天气加载失败显示“天气暂不可用”，未选地区显示选择提示。切城市立即清除旧温度，较早的响应不会覆盖当前城市。

**生产环境尚未部署该接口，腾讯 Key 的天气服务权限和真实温度链路尚未验证。** 新版前端连接尚未更新的后端时会显示“天气暂不可用”，不能把验收样例温度当作线上实时数据。小程序请求仍统一经现有 API 域名，无需把地图 Key 或临时天气域名放进前端。

API 与签名依据 [腾讯位置服务官方技能](https://github.com/TencentLBS/tencentmap-webservice-skill/blob/main/references/api-location-weather.md)核对。

## 继续参考 GameConnect 的美化空间

| 优先级 | 方向 | 具体做法与验收重点 |
| --- | --- | --- |
| 高 | 赛事卡片的信息层级 | 使用左侧封面与日期时间、右侧标题与报名状态的布局；人数和截止时间集中展示。先核对列表接口实际字段，避免编造状态、距离或赛事格式。320px 屏宽和长标题需专项验收。 |
| 高 | 首页筛选密度 | 将排序、类型、等级压成更紧凑的胶囊；日期和“适合我的级别”保留明显但较弱的入口。加实际结果数量，区分总数与已加载数量，明确筛选生效状态。 |
| 高 | 赛事长表单 | “基本信息 → 报名 → 赛制”逐级展开，压缩封面空态高度，给必填项更明确的优先级。保持编辑、草稿和赛程预览行为。 |
| 中 | 详情页首屏 | 时间、地点、报名人数形成紧凑事实区；将主按钮与辅助操作分层。较长页头可评估滚动后收紧，保留地区选择和返回操作。 |
| 中 | 场地时段表 | 固定时间列、横向滚动提示与更清晰的选中金额，避免多球场把文字挤成多行。 |
| 中 | 内容与响应式验收 | 真实封面、缺图、长名称、未登录、大字号以及 320/390/430px 宽度检查；真机胶囊、安全区和键盘体验仍需补验。 |

不复制参考中的多运动分类、自定义凸起 tabBar 或与本项目无对应功能的按钮。
