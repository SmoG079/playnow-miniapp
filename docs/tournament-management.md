# 赛事发布、抽签与管理实现说明

本次实现保留网球、俱乐部管理权限、原生五个 tabBar 和 AppShell。历史赛事不会自动补赛制；管理员编辑配置并核验历史付费报名后，才能进入新抽签流程。未发布的抽签草稿、审核原因、付款与联系方式等报名私有字段不向公众返回。

## 发布入口与权限

底部“发布”页顶部增加“发布比赛 → 创建比赛”入口，原“我的 → 俱乐部管理 → 创建赛事”入口保留。普通 `user` 不展示赛事入口，直接访问赛事创建页会提示权限不足并返回发布页；自由约球仍可发布。

当前项目的俱乐部账号是 `club_admin`，且需要 `managed_club_ids` 中存在所属俱乐部；只能为所属俱乐部预览、发布和管理赛事。`platform_admin` 可以为所有俱乐部发布。前端入口、赛事创建页与 `canManageClub` 统一角色及归属判断，后端仍以 `get_club_admin` 校验，不能凭前端显示放行。普通 `user` 即使带有历史俱乐部关联记录也不会获得赛事发布权限。

本次入口补充验证：前端 16 项测试、类型检查、小程序生产构建与上传 dry-run 通过；赛事算法/流程及权限矩阵共 38 项后端测试通过。Wot lint 保留之前已核对的八处子组件识别警告，没有新增警告。未部署或上传。

## 用户与管理员流程

1. 管理员在发布页填写跨日期起止时间、地址或关联场地、图片（最多六张，第一张为封面）、介绍、奖项、联系人。标题可自动生成，介绍支持 `{{日期}}`、`{{时间}}`、`{{地点}}`、`{{项目}}` 模板。
2. 选择淘汰、循环、循环接淘汰；单打、双打或混双；配置分组、场地名称、每场估算时长。折叠区提供审核、候补、两个截止时间、不分组展示、季军赛、允许循环平局、并行场次及晋级名额。收起时显示摘要，校验失败展开相应区域。
3. 发布前预览在客户端计算，无需新后端接口，也无需填完名称、介绍和报名高级设置；使用虚拟队伍，不写正式签表。组合赛同时预览小组与淘汰阶段；估算包含轮空、并行场地、前置轮次及结束时间超限提示。
4. 报名按个人占位。免费报名直接确认；付费报名审核通过并获得名额后，预留最多十分钟支付。候补不先收款，递补按报名顺序及混双性别容量限制处理。
5. 报名可选择参赛组或自动分组，抽签保持所选组别；组内人数和混双性别配额按事务校验。固定搭档须选同组或双方都自动分组。未冻结时可更改组别。固定搭档通过小程序分享邀请确认，双方须各自报名、审核及支付。邀请不占对方名额。随机搭档在抽签时配对；混双使用本人填写的性别。搭档退出保留另一人报名并提示重新配对。
6. 管理员关闭报名冻结名单，生成抽签草稿，再明确发布。开赛时间不会自动抽签。未完成固定配对、奇数双打或混双比例不足会阻止抽签。
7. 签表按组横向滚动，展示轮空、前置胜负者来源、队伍、比分及场地时间，突出本人队伍。详情另有介绍、参与者、赛程、排名分页。公众只能查看已发布版本；管理员可查看草稿及历史版本。
8. 管理员排场、录分、选胜者或弃权。循环赛可按配置录平局；淘汰必须有胜者。自动晋级、自动排名；已有下游结果时拒绝上游修改，必须先从下游撤销。
9. 循环同分先比较两队直接交手；多队或仍相同时提交该组全部队伍 ID 的顺序与理由，只影响对应积分同分区间。小组赛全部完成并处理同分后，另抽淘汰阶段，首轮尽量避开同组队伍。
10. 同阶段可填写原因重新抽签并发布新版本。已产生结果时，界面另要求明确确认归档，服务端要求 `archive_results=true`，旧签表及比分保留在历史版本中，新版本从未录分开始。组合赛不能退回初始阶段，可重抽当前淘汰阶段。

比赛场地标签用于排场，关联项目场地会检查俱乐部归属，不自动创建或锁定真实场地预约。比分是自由文本，不解析网球盘局或净胜指标。管理员可调整报名不足赛事或取消，没有自动取消任务。

## 预览、个人对阵与更新（2026-10-07 补充）

预览弹层按参考页面展示赛制说明、场数、轮次、预计时长、场地及按组排列的晋级树。连线来自真实前置场次关系；淘汰阶段显示决赛、半决赛、四分之一决赛等标题。横向滚动查看后续轮次，纵向滚动查看其他组。预览仅校验赛制人数与起止时间，避免发布表单未填完时按钮无响应。

正式签表发布前，已确认名单满足每组两队、配对及性别条件时，详情提供临时真实选手对阵预览，明确提示随报名变化，不写抽签版本或结果。报名不足或未配对时继续显示虚拟赛制结构和待抽签。

“我的报名”新增“我的比赛”分页，数据来自服务端报名关系；展示本人组别、上/下半区、已知对手、待晋级对手、比赛时间和场地。与赛事详情均在页面可见时每五秒刷新，离开页面停止轮询。记录引用最新已发布版本；草稿不替换公众版本，历史签表仍可手动查看。此处的同步是五秒轮询，不是 WebSocket 推送。

新增 `POST /tournaments/{id}/group` 和 `GET /users/me/tournaments`，报名请求增加 `requested_group`（0 为自动分组）；抽签请求增加 `archive_results` 和 `publish`。未部署的赛事迁移版本增加同名报名列及默认值，不修改线上数据库。

本次验证：后端 69 项通过，10 项暂缓预订支付测试仍按既有约定排除；前端 23 项测试通过，另有类型检查、小程序构建及上传 dry-run。隔离 H5 浏览器拦截所有外部请求：验证空标题直接打开本地预览、八人两组六场/四条晋级连接、零后端预览请求，以及模拟发布新版本后详情和个人记录自动刷新。浏览器测试使用模拟接口，不代表真机或线上后端已验收。Wot lint 保留八处已核对的子组件识别警告。

## 数据与接口

Alembic 新版本 `20261007_tournaments` 接在 `20261007_schema_alignment` 后。增加赛事配置、报名审核/候补/付款/配对字段及队伍、成员、抽签版本、比赛场次、审计表。订单增加 `business_type` 与赛事外键，赛事订单允许场地为空。历史付费报名标记 `unverified`，旧赛事关联订单回填业务类型；`dev_` 交易号不视为真实收款。管理员的历史核验只确认参赛资格，不生成支付凭据或真实退款资格。

接口以 `/api/v1/tournaments` 为前缀：

| 操作 | 方法与路径 |
| --- | --- |
| 发布、编辑、详情 | `POST /`、`PUT /{id}`、`GET /{id}` |
| 虚拟预览 | `POST /preview` |
| 报名 | `POST /{id}/register` |
| 审核、取消、全额退款、历史核验 | `POST /{id}/registrations/{reg_id}/review`、`cancel`、`refund`、`verify-payment` |
| 搭档方式与邀请确认 | `POST /{id}/pairing`、`POST /{id}/invitations/{token}/accept` |
| 支付、服务端查单 | `POST /{id}/pay`、`POST /{id}/payment-status` |
| 关闭报名、抽签、明确发布 | `POST /{id}/close-registration`、`POST /{id}/draw`、`POST /{id}/draw/publish` |
| 历史签表 | `GET /{id}/draws/{version}` |
| 排场、录分、撤销结果 | `PUT /{id}/matches/{match_id}/schedule`、`PUT .../result`、`POST .../reset` |
| 同分顺序、结束、取消、审计 | `POST /{id}/tie-order`、`POST /{id}/finish`、`POST /{id}/cancel`、`GET /{id}/audit` |

所有管理操作复用服务端俱乐部归属鉴权。抽签使用赛事行锁、预期版本、幂等键及数据库唯一约束；报名、确认、取消、退款和维护任务统一赛事 → 订单的锁顺序。签表与结果使用关系表，不保存成图片。业务时间按上海展示，内部按 UTC-naive 比较。

## 赛事支付与退款

`TOURNAMENT_PREPAY_ENABLED=false` 默认关闭付费报名及支付入口。免费赛事可完整运行。`TOURNAMENT_SEAT_TTL_SECONDS=600` 控制占位时长，报名截止更早时按截止时间释放。

客户端首次报名只使用赛事支付接口；微信支付完成显示确认中，最终由验签回调或服务端查单确认。金额来自订单快照。赛事回调核对商户、应用、金额及交易号，事务提交后才应答成功；重复通知不重复确认名额。迟到成功通知不会恢复失效名额，而是创建全额退款记录。

Celery Beat 每分钟调用 `maintain_tournaments`，处理截止冻结、席位过期、候补递补、关单/查单和退款恢复。每个任务使用独立无池数据库连接，避免跨事件循环复用。退款采用固定 `TR{order_id}` 单号，先查原单核验真实收款，再申请退款，核对退款响应并轮询或接收回调确认最终结果。失败按既有重试次数和退避参数重试；达到上限需管理员核对后重新发起。异常、关闭状态进入人工处理，不恢复参赛资格。

退款申请受理不等同退款完成。微信 `ABNORMAL` 需要商户平台或异常退款接口处理，`CLOSED` 是终态，本实现提示管理员在商户平台处理并核对最终结果，避免普通申请接口盲目重试。参见[微信支付退款开发指引](https://pay.wechatpay.cn/doc/v3/merchant/4013071031)。

自助取消截止前全额退；截止后管理员填写原因全额退。主办方取消赛事退出全部参赛者并创建已收款订单全额退款。退款失败不恢复报名。赛事退款与关单不释放预约时段、不触发赛事分账；真实场地预订支付和退款仍暂缓。
