# 用户记录与俱乐部数据保存检查

## 本次修复

- 微信用户资料继续以数据库 `users` 为准。比赛报名、分组和签表查询来自当前用户的服务端接口；新约球报名列表使用 `/users/me/post-registrations`，不再读取或维护本地 `registered_post_ids`。
- 约球列表按当前用户过滤，支持分页，保留无俱乐部的自由约球及关闭活动。失败时显示重试提示，两类记录分别处理错误，不把请求失败当作空记录。
- 约球取消报名改为 `cancelled` 状态，保留数据库记录，释放名额；重复取消安全，重新报名复用同一记录。已取消记录不能被管理员审核恢复。此处保存的是该用户在该活动中的当前报名状态，并非每一次状态变化的完整事件日志。此前物理删除的报名记录无法自动恢复。
- 退出及重新登录清理旧账号的临时订场回传和旧本地报名 ID。退出后到达的资料或刷新令牌响应不能恢复旧登录。
- 新增 `/clubs/managed`，俱乐部管理员只能读取自己关联的俱乐部，平台管理员可分页查看所有俱乐部，包括未关联自己和停用的俱乐部。管理页重新读取权限及管理列表；后端继续校验具体俱乐部归属。
- 修复创建俱乐部未保存规则、详情未返回营业时间，以及编辑营业时间未转换为数据库时间类型的问题。资料更新校验营业时间，保留未修改的资料字段。
- 修复新建场地未保存价格规则的问题，未改动预约真实支付及价格计算规则。

剩余本地持久化内容为登录凭证和读取后删除的 `booking_return` 临时回传；俱乐部、场地、订单、用户资料和正式报名数据不以本地存储为唯一来源。

## 验证与边界

- 后端隔离 SQLite 及现有 CI 回归：71 项通过，10 项延期预约支付测试按原规则排除。额外自由约球查询 3 项通过。覆盖跨数据库会话读取、53 条记录分页、账号隔离、取消/重新报名、俱乐部及场地资料往返保存、越权编辑、权限变更和平台管理员列表。
- 前端类型检查及 32 项测试通过；小程序生产构建和上传 dry-run 通过，没有上传。Wot lint 无错误，现有赛事页面仍有 8 条组件元数据警告。
- 开发者工具在隔离构建及模拟请求下完成 12 步验证：无本地报名 ID 仍显示比赛及约球记录，取消状态正确，失败显示重试提示。非真机或线上接口验收。
- 新增迁移 `20261007_post_history` 扩展约球报名状态枚举；生成的 MySQL SQL 已检查。缺少隔离 MySQL 环境，空库升级、重复升级、历史结构升级的 3 项集成测试跳过，不计为通过；MySQL 行锁并发未实测。存在取消记录时禁止降级，以免损失记录。
- 未部署、未修改线上数据库。正式启用前需在隔离 MySQL 完成迁移演练，并一起发布匹配的前后端。不能据本次检查承诺线上所有功能绝无异常。

本次只检查数据来源及所列保存/读取问题；现有 PDF 上传限制、统计利用率占位、延期场地支付退款等边界仍按各自待办处理。
