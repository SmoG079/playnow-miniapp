# 用户 OpenID 主键迁移与体验版登录修复（2026-10-08）

按用户明确确认，users.id 从 BIGINT 自增编号迁移为微信 openid 字符串。所有引用 users.id 的外键、API 用户编号、JWT subject、前端参赛者及搭档类型同步切换；比赛、约球、场地、队伍与比赛场次的业务编号继续保持数值类型。主键和 openid 唯一约束防止同一 OpenID 重复开户，并发首次登录冲突后读取已经创建的用户。

openid 随 AppID 变化，不实现跨 AppID 自动识别；不根据昵称自动合并账号。此次已确认的两个账号计划单独合并，保留当前小程序身份并恢复旧账号的俱乐部管理员角色，迁移所有关系和签表历史引用。用户编号不在个人资料页面展示。

Alembic 20261008_user_openid 保留 legacy_id → openid 映射，预检缺失身份、重复身份、孤儿外键和不支持的复合键。转换用户外键、签表名单快照及审计中的用户引用，保留有效 Redis 预约锁的 TTL。MySQL DDL 失败后不自动降级或重试，按正式备份恢复边界处理。

旧版未绑定 AppID 的本地登录缓存首次升级时清除，之后保存当前 AppID 和 API 环境绑定的令牌。我的页面在确认用户信息前不展示兜底用户卡片。头像上传和普通请求共享并发令牌刷新，区分上传域名、网络、服务端和大小错误；头像仍上传 COS。手机号输入框采用 tel 类型并把微信填写按钮放入框内，获取手机号不覆盖未保存的昵称；权限缺失或拒绝授权时允许手填。微信 access_token 缓存按 AppID 隔离，正式模式禁止 mock 手机号授权。
