# 抽签失败提示修复（2026-10-09）

生成抽签草稿时，后端校验错误已由 `api.ts` 转为 Error，但赛事详情页直接等待请求，没有捕获拒绝，导致只有调试日志而没有用户提示。

在赛事详情的抽签流程捕获失败，通过已有的 `uni.showModal` 显示后端原始原因。首次抽签标题为“生成抽签失败”，重新抽签为“重新抽签失败”，缺少错误消息时使用通用重试提示。保留请求函数中的 finally，失败后释放按钮加载状态，不刷新签表、不改变抽签版本。生成淘汰阶段签表也走相同处理。

## 开发者工具验收

请求及存储均使用临时 mock，未操作线上报名或抽签数据。

- 模拟抽签接口 HTTP 422，错误为“每组至少需要两队，请调整分组报名或补充参赛者”。实际点击“生成抽签草稿”，原生弹窗完整显示标题、原因与“知道了”。
- 关闭弹窗后按钮 disabled=false，可再次点击；重复失败仅发出 POST draw，没有详情刷新，draw_version 仍为 0。
- 将模拟请求恢复成功后再次点击：POST draw 后 GET 详情，按钮改为“重新抽签”，版本变为 1。
- 本次抽签错误及 Uncaught / Unhandled 日志查询无匹配。模拟器刷新前尚未部署的天气路由曾返回 404，属于本轮待上线功能。
- 验收后恢复 request、showModal 及存储 mock，并刷新模拟器。
