# 队伍报名、主办方联系与创建表单

双打及混双由发起者必选固定或随机搭档，报名者不能再覆盖比赛的搭档方式。比赛创建时建立持久队伍：单打一人一队，双打/混双两人一队。固定搭档在参与者页按队伍展示两席，点击空位报名或换队，混双固定为男、女各一席。随机搭档在报名取得席位时安排队伍；抽签只打乱已有队伍的顺序，不再配对个人。每组至少两支资格已确认且人员齐全的队伍才能抽签。

队伍席位独立于各版签表快照。审核和待支付席位不能重复选择；拒绝、取消、过期释放席位，原搭档保留参赛资格并可继续邀请。换队和邀请均走赛事行锁，MySQL 当前读及唯一席位约束防止重复占位。名单冻结后不可换队。待确认席位向公众显示已占位，审核、支付及身份资料只按已有权限返回。

个人主办通过小程序私信联系发起者；俱乐部主办保留电话入口。私信上下文统一为全局活动 ID 和活动类型，继续复用双方会话，活动卡片支持跳回约球或比赛。

创建约球和比赛使用统一的白底边框分组卡片、字段间距、输入框和按钮排布。参数说明通过问号打开弹窗，常驻文字保留字段名称、单位及实际选项。两类报名审核使用头像、昵称及真实 NTRP 标签，未设置等级显示“未定级”。

迁移 `20261015_entry_teams` 一次性补齐已有比赛配置和队伍，优先保留已有签表队伍、组别和互相确认的搭档，不修改旧签表或比赛结果。报名个人搭档字段删除；私信 `post_id` 改为 `activity_id`，原会话和已读位置保留。没有旧字段双读、旧客户端参数回退或抽签时临时配队路径，客户端需配套更新。

验证：前端类型检查、200 项测试、生产构建与上传 dry-run；后端全套及本次资格、席位、邀请、私信测试；MySQL 同一空位并发报名、并发抽签、私信并发重试及前版本迁移测试。隔离空库完整升级、重复升级、线上只读快照恢复升级及模型结构核对通过；除上述明确迁移的字段外，恢复副本原有列数据哈希一致。支付验证为隔离测试，不代表真实收款和退款验收。模拟器仅使用模拟报名数据，未替用户报名或发送私信。未上传体验版。
