# 预订支付与退款边界

## 当前实现（2026-10-14）

真实订场预支付已恢复到当前代码：`WX_PAY_ENABLED=false` 时为占位确认，直接标记 paid 并生成 `dev_` 交易号；`true` 时调用微信预支付及客户端收银台，最终由真实回调或服务端查单确认收款。2026-10-13 的“预支付分支已注释、开关不能恢复”说明是当时版本记录，已不代表当前工作区。本次未读取或修改线上开关。

本轮按真实收款可能开启的前提修复资金安全，详见 [修复与验证记录](business-payment-fixes-20261014.md)：

- 已启用自助取消：按预约首个时段的上海时间判断，超过开始前 1 小时可取消；恰好 1 小时、1 小时内及开始后不可取消。真实已付款订单全额申请原路退款，先持久化 refunding，退款确认后释放时段；待支付与 `dev_` 占位订单只取消、不伪造真实退款。重复请求复用原单。参见 [自助退款验证](booking-self-refund-20261014.md)。
- 管理员可申请全额或指定金额退款，包括历史已取消但有真实收款的订单。先持久化退款意图、单号、金额和 refunding 状态，再由定时任务处理。一个订单的一次业务退款复用原单，不支持另发单号追加部分退款；历史多笔退款需要先人工核对。
- 微信受理不等于退款成功。网络错误时先查原退款单，不恢复 paid、不自动换号。失败达到上限保留原申请并通知用户，管理员核对后可重新调度原单；closed/abnormal 需商户平台处理。
- 订单本地超时或取消后收到真实成功通知，记录交易号并申请全额补偿退款，不恢复场地。部分时段失效时也不确认剩余时段的部分预约。
- 预支付绑定本地锁期限，调用前保存可恢复的支付申请日志；每分钟的 `maintain_booking_payments` 查询尚未完成的真实交易，并对已取消且未付款交易关单。预支付响应丢失仍可恢复查询。
- 回调、退款重试与轮询按订单 → 退款记录 → 时段加锁；只释放本订单仍拥有的时段，Redis 锁值统一为 `booking:{order_no}`。

这些代码和模拟验收不代表真实商户资金链路已验收。上线时需更新 API、Celery Worker 与 Beat，保留原有商户配置；小程序上传与真机验收是独立流程。

## 仍暂缓的范围

- 旧 24 小时全退、24 小时内半退规则已由负责人明确替换为“超过 1 小时全退，其余不可取消”，不再作为当前目标。
- 自动分账仍暂缓；分账记录和 SDK 代码存在不表示资金验收完成。
- 必须单独完成受控小额的真实收款、重复/迟到通知、查单、关单、管理员退款、失败恢复及最终到账验收；同时确认 Worker/Beat 运行与回调可达。

## 历史约定与测试范围

2026-10-07 决定暂缓真实订场支付与取消退款；2026-10-13 的占位版本仍由负责人要求暂缓真实收款。当前预支付分支已恢复，以上历史决定保留其版本边界。

10 项历史支付/取消测试仍保留 `deferred_booking_payments` 标记，CI 使用 `-m "not deferred_booking_payments"` 排除。它们仍包含过期查询模拟和已被新规则替代的阶梯退款合同，未删除断言或用 xfail 隐藏；默认运行全部测试仍会执行这些历史用例。新增资金安全回归、支付同步、退款恢复和 MySQL 并发用例已加入 CI，不使用暂缓标记。

新自助规则已用独立、未标记为暂缓的真实 SQL 回归测试覆盖并加入 CI。旧标记保留其历史合同边界，未删除或弱化旧断言；后续整理旧合同和查询模拟、完成真实资金验收后再移除排除条件。CI 通过仍不能表述为真实资金链路已通过验收。
