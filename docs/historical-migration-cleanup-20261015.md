# 一次性迁移与历史兼容清理（2026-10-15）

按本次要求，历史数据直接迁移到当前结构，不保留旧客户端和旧接口格式的兼容分支。

- 约球人数只使用包含发起人的 min_players/max_players；旧报名名额加 1 转为最大人数，最低人数设为 2。迁移保留报名记录，发起人的重复报名转为取消历史。
- 预订单只保留 slot_ids，删除 slot_id 列及 ORM 关系、响应字段和回退读取。迁移合并旧单时段、数组和 booking_slots 关联并按实际日期时间排序，补齐关联，不推算历史分时段价格，也不修改收退款状态。无法恢复的时段引用会阻止迁移，不跳过。
- 比赛只保留结构化 prizes。仅当原结构化数据为空值时转换旧 prize 文本；显式空数组仍表示清空奖项。转换后删除旧列、旧请求字段、前端文本回退及旧服务端重试。
- 活动只接收当前统一 ID，删除旧 ID 别名查询、activities.legacy_id 和已完成迁移的 user_id_migrations 映射表。已有业务外键使用当前 ID，不重新编号。
- 签位在创建或一次性迁移时写入 snapshot.positions，详情和调整签表不再运行时推断旧签位。
- 旧价格规则名称 time_range 一次性转换为 daily_time，保留匹配顺序和金额，服务端与前端不再支持旧别名。
- 删除未使用的时段 price_override 列、废弃 FREE_CANCEL_HOURS 配置，以及已无调用方的旧比赛请求/响应定义；前端直接使用服务端抽签校验和参与名单。

迁移链为 `20261014_direct_messages → 20261015_post_people → 20261015_remove_legacy → 20261015_price_rule_names`。迁移不可自动降级；正式发布按停写、备份、迁移、健康验收顺序执行。历史迁移文件保留，保证空库和已有版本库均可升级。

数据库枚举/时间类型适配、占位支付识别、支付退款异常恢复、未核验收款的人工资格核验、未配置 COS 时的本地存储仍是当前业务和运行保障，不属于格式兼容。不会推定历史收款成功、重建无法证明的金额，或删除本地存储仍使用的上传入口。

验证覆盖隔离空库和正式只读备份的恢复副本升级、重复升级，恢复副本订单金额/支付/退款记录摘要不变；独立 MySQL/Redis 并发报名、预约、重订、退款和消息检查。新增迁移回归覆盖单时段转换、奖项转换、历史签位持久化和旧列删除，已加入 CI。
