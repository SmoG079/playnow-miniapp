# 社群与活动提现（2026-11-02）

## 行为

俱乐部按用户社群展示。名称、简介、城市、联系电话必填，LOGO、宣传图和具体地点选填；无场地可创建并在本地列表展示。创建沿用审核；通过后群主进入普通成员表。普通成员独立于管理员关系，加入不会获得后台权限；支持加入、退出、群主移除，群主不能直接退出或移除自己。

底部五个原生入口保留，第二项改为俱乐部。旧订场链接进入暂停说明页；后端默认拒绝新增预约、待付预约付款及场地经营修改。历史查询、查单、取消、退款保持可用。活动地图地点独立于平台订场；比赛主办社群查询包含无场地俱乐部。分账任务和直接执行入口同时受暂停开关约束，不会伪造分账成功。

“我的”和俱乐部工作台提供活动提现。俱乐部筛选仅展示本人相关活动，不能提取其他创建者收入。真实线上收款形成逐订单收益归属记录；线下、免费和 dev_ 占位收入不计入。历史真实收款由迁移回填当前创建者归属；新收款在确认时保存归属，不随之后的活动资料变化转移。

活动结束 24 小时后解锁，付款时保存最早解锁时间，之后缩短活动不能提前解锁，延后活动按较晚时间处理。历史缺失结束时间的记录不自动解锁。退款中、异常和存在退款记录的款项冻结。

平台费为 0，微信支付手续费默认按逐笔订单金额 × 0.006 四舍五入到分估算。正式申请前必须核实商户签约费率；首次申请时保存费用快照，分批提现不重复扣费。商家转账自身不再另收费用。页面明确区分估算与按签约费率计算的费用，尚未接入微信支付账单下载与差异自动对账。

## 资金与接口

新增 `activity_earnings`、`activity_withdrawals`、`activity_transfers`。申请保存逐订单分配、单笔转账单号、收款账号及商户场景快照，提交外部请求之前先提交数据库。相同用户和 request_key 重复申请复用原记录。超时不换单号，保持冻结并查原单；仅微信明确失败或取消释放相应金额。客户端打开确认页成功不等于到账，以验签响应、查单或验签回调为准。

- `GET /activity-wallet`：本人账户、按活动汇总、日期／俱乐部筛选及提现记录。顶部余额始终为本人整个账户。
- `POST /activity-wallet/withdrawals`：`request_key`、可选 `activity_ids`，返回本次实际金额与拆单列表。账户余额、单笔和单用户每日额度均由后端检查。
- `POST /activity-wallet/transfers/{id}/sync`：本人发起／查原单，待领取时返回微信确认页参数。
- `POST /activity-wallet/notify`：独立转账通知，校验时效、签名、原单及金额／身份。
- `GET/POST/DELETE /clubs/{id}/community`：成员状态、加入和退出；`DELETE /clubs/{id}/community/{public_id}` 仅群主移除普通成员。

同用户申请在用户行上串行化，余额输入使用当前锁定读取，避免 MySQL REPEATABLE READ 的旧快照导致重复提现。单笔默认 10–20000 分，同用户每日默认 20000 分；未终结转账即使跨日仍占用额度，成功款按到账日统计。超过每日额度仅申请本次允许金额，其余之后申请；拆单不能突破每日限额。转账查单由每分钟 Celery 任务兜底。

正常退款不因组织者已提现而被阻止。未提交的转账在来源失效后取消；已经提交／到账的转账继续核对，退款产生账户待抵扣金额，由后续已解锁收入优先抵扣，期间不允许超额提现。平台承担资金先行退款及异常人工核对工作；本次不新增催缴、银行卡还款或平台垫资自动核销功能。

## 配置与启用

开发／回归环境明确设置 `CLUB_BOOKING_ENABLED=true` 以保留历史订场验证；发布默认 false。不能把测试开关复制到正式环境。

真实转账默认关闭，以下条件必须全部满足：

- `WX_PAY_ENABLED=true` 且既有真实支付商户配置完整。
- `ACTIVITY_TRANSFER_ENABLED=true`。
- `ACTIVITY_TRANSFER_SCENE_VERIFIED=true`：获批场景确实覆盖实际业务用途；竞品的“活动奖励”文案不能代替适用性核实。
- `ACTIVITY_TRANSFER_SCENE_ID` 和 `ACTIVITY_TRANSFER_REPORT_INFOS`：填商户真实获批场景 ID 及对应字段，不自动将报名收入改报现金奖励。
- `ACTIVITY_FEE_RATE_VERIFIED=true` 及 `ACTIVITY_PAYMENT_FEE_RATE`：核实签约费率后设置，默认估算 0.006。
- `ACTIVITY_TRANSFER_LIMITS_VERIFIED=true`：核实并设置 `ACTIVITY_TRANSFER_MIN_CENTS`、`ACTIVITY_TRANSFER_MAX_CENTS`、`ACTIVITY_TRANSFER_DAILY_CENTS`。本次单笔最高仍限制 20000 分。
- 可选 `ACTIVITY_TRANSFER_NOTIFY_URL` 指向独立 HTTPS `/api/v1/activity-wallet/notify`，未配置时依赖定时查单。

`REPORT_INFOS` 为 JSON 对象数组，各项包含获批场景要求的 `info_type` 和真实 `info_content`；不要在公开配置中保存任何密钥。商户配置变化时，旧单继续核对原商户，不能切换商户重发；当前实现对不匹配配置拒绝自动处理并要求人工核对。

官方依据：[额度](https://pay.wechatpay.cn/doc/v3/merchant/4013747667)、[发起转账](https://pay.wechatpay.cn/doc/v3/merchant/4012716434)、[小程序确认收款](https://pay.wechatpay.cn/doc/v3/merchant/4012716430)。
