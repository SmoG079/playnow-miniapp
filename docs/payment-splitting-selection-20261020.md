# 分账方案选型报告（2026-10-20）

> 场景：网球场地预约 + 比赛报名，每笔订单 95% 分给场馆 / 比赛发起者，平台留 5%。

## 一、先把前提纠正过来

「接入第三方支付」在小程序里**做不到**。《微信小程序运营规范》明确：小程序交易场景仅允许接入微信支付，禁止内嵌、跳转、引导支付宝等第三方支付通道（web-view、收款码、Scheme 均属违规，处罚为审核驳回→功能封禁→主体注销）。

**能做的只有「第三方分账」**：收单仍是 `wx.requestPayment`（微信支付），资金清算/清分环节交给持牌机构。

所以真正要选的是：**谁来做资金清分**，而不是「用谁的支付通道」。

## 二、你项目里的现状（决定了改造量）

| 现状 | 位置 | 影响 |
|---|---|---|
| `Club.sub_merchant_id` 字段已存在 | `models.py` | 架构**已按服务商/特约商户模式预留** |
| `SettlementRecord` + `execute_settlement()` 已实现微信分账调用 | `services/settlement.py` | 分账骨架完整，含金额校验、失败重试、状态查询 |
| 分账接收方用 `MERCHANT_ID`（= `club.sub_merchant_id`） | `settlement.py:73` | 只能分给**有商户号的主体**，个人不行 |
| `PROFIT_SHARING_ENABLED=False`，下单带 `settle_info{"profit_sharing": False}` | `config.py` / `bookings.py:311` | 当前只记账、不真实分账 |
| `Club.split_ratio` 默认 `0.100`（平台 10%，场馆 90%） | `models.py:93` | ⚠️ **当前结构会撞 30% 上限** |

**关键问题**：现有实现是「**平台商户号收款 → 分 90% 给场馆**」。微信分账单笔上限 30%，这条路走不通。

**正解是把它反过来**：让**场馆作为子商户直接收款 100%**，平台再分走 5%（≤30%，完全够）。分账方向一换，30% 限制就不再是问题。

## 三、三条可行路线

### 路线 A：微信服务商模式（行业标准解法）

```
用户付款 → 场馆子商户号（T+1 直结） → 平台分账抽 5%
```

| 维度 | 说明 |
|---|---|
| 分账比例 | 平台抽佣 ≤30%，你只需要 5% ✅ |
| 合规性 | 最高（资金不过平台账户，微信官方清分） |
| 成本 | 仅支付费率 **0.6%**，分账免费、无接入费 |
| 体验 | 场馆 T+1 到账，不压款 |
| **准入门槛** | ⚠️ **服务商仅面向「有限责任公司/股份有限公司」开放，个体工商户申请不了**（官方原文） |
| 个人接收方 | 分账支持 `PERSONAL_OPENID`，可给比赛发起者个人打款 |
| 改造量 | 小（`sub_merchant_id` 已在，改成「子商户下单 + 反向分账」） |

> 同类产品（易馆通等体育场馆预约系统）走的正是这条路：*「资金走微信支付服务商模式直达商户号，T+1 结算」*。

### 路线 B：第三方持牌机构「空中分账」

```
用户付款 → 持牌机构备付金/监管专户 → 按 95/5 清分到各方
```

| 维度 | 说明 |
|---|---|
| 分账比例 | **0–100%**，不受 30% 限制 |
| 合规性 | 合规（前提：真持牌 + 资金不落地平台，符合央行 217 号文） |
| 成本 | 支付 0.38%–0.6% + 分账 0.1%–0.6%/笔；部分收接入费 1–5 万 |
| 门槛 | 营业执照即可，**个体工商户可接入** |
| 个人接收方 | 支持对私（银行卡/微信零钱） |
| 改造量 | 中（要换支付网关、重做回调/退款/对账） |

### 路线 C：微信直连分账 + 提额申请

| 维度 | 说明 |
|---|---|
| 分账比例 | 默认 30%；50% 走品牌专区供应链分账申请；>50% 需发邮件至 `WeChatPayFunds@tencent.com`，3–7 工作日 |
| 通过率 | **中小平台、新主体通过率低**（要平台存续时间 + 交易体量 + 售后体系） |
| 成本 | 最低（仅 0.6%） |
| 结论 | 要 95% 基本不现实，**不建议作为主方案** |

### 伪方案（必须避开）

**平台收款 → 人工/系统转账给场馆** = 二清。央行 217 号文红线，与金额大小无关；哪怕月流水几千也算违规。

## 四、成本测算（单笔 100 元订单，平台抽 5 元）

| 方案 | 支付费率 | 分账费 | 场馆到手 | 平台到手 | 备注 |
|---|---|---|---|---|---|
| A 服务商模式 | 0.6 元 | 0 | 94.4 元 | 5.0 元 | 费率由场馆承担时可全额转嫁 |
| B 第三方（轻量） | 0.6 元 | 0.2 元 | 94.2 元 | 5.0 元 | 平台承担分账费则净得 4.2 元 |
| B 第三方（持牌大厂） | 0.6 元 | 0.3–0.6 元 | 94.2 元 | 4.4–4.7 元 | 另有接入费 1–5 万 |
| C 微信直连 | 0.6 元 | 0 | 94.4 元 | 5.0 元 | 比例受限，实际不可用 |

**结论**：成本差异在 0.2%–0.6% 区间。对 5% 抽佣来说，第三方比分账方案多消耗 4%–12% 的平台收入。体量小时无所谓，月流水 30 万时差 600–1800 元/月。

## 五、推荐路径（分阶段）

| 阶段 | 场景 | 方案 | 理由 |
|---|---|---|---|
| **现在** | 自营场馆 / 单一主体 | **不分账**，平台直收 | 都是自己的钱，不需要分 |
| **过渡期** | 出现 2–3 家合作场馆，月流水 < 20 万 | **路线 B（0 接入费的轻量方案）** 或 **场馆直收 + 月结服务费** | 个体户可用，快速上线 |
| **成长期** | 多场馆、月流水 > 20 万 | **升级有限公司 → 路线 A 服务商模式** | 成本最低、体验最好、最合规，长期唯一正解 |

**如果只记一句话**：**个体户是天花板，服务商模式才是你的终局；第三方分账是过渡桥，不是终点。**

## 六、供应商清单与核验方法

### 路线 A（需公司主体）
- 微信支付服务商：公众平台 → 微信支付 → 服务商申请（需企业类型服务号 + 对公账户）
- 申请条件：有限责任公司/股份有限公司、2 名以上熟悉支付业务的高管、健全风控制度

### 路线 B（持牌机构）
| 机构 | 特点 | 参考成本 |
|---|---|---|
| 拉卡拉分账通 | A 股上市，牌照可查，线下+线上统一对账 | 接入费 1–3 万，分账 0.25%–0.6% |
| 汇付天下 | 产业互联网深耕，API 完善 | 接入费 1–3 万，0.25%–0.4% |
| 富友支付（富管家） | 行业模板多，中小商户友好 | 接入费较低 |
| 通联支付 | 连锁业态成熟 | 中等 |
| 银联商务 | 国资背景，合规等级最高 | 偏高 |
| 收钱吧分账通 | 0 开户费/0 年费，最低月费约 50 元 | 分账 0.1%–0.2% |

> ⚠️ **MallBook、分账链这类是 SaaS 技术服务商，本身通常无支付牌照**，必须确认其底层持牌机构是谁。

### 核验方法（必做）
1. 央行官网 → 政务公开 → **支付业务许可证**公示 → 搜机构全称
2. 确认牌照业务范围含「互联网支付」
3. 合同里写明：资金进入该机构**客户备付金账户**，平台无划拨权
4. 拒绝「挂靠牌照」「联合清算」话术

## 七、代码改造要点

**路线 A（推荐终局）**
1. 下单时传 `sub_mchid`（场馆子商户号）+ `sub_openid`，资金直接进场馆
2. `settle_info` 打开 `profit_sharing: true`
3. 分账接收方改为**平台自己**（抽 5%），而非现在的「分 90% 给场馆」
4. `Club.sub_merchant_id` 改为必填校验（进件未完成的场馆不给上架）
5. 比赛报名：发起者为个人时用 `PERSONAL_OPENID`，需其在本 appid 下授权

**路线 B**
1. 新增支付网关适配层，保留 `payment.ts` 接口不变
2. 回调验签改为持牌机构密钥体系
3. 退款需按「已分账回滚」规则处理（第三方通常支持自动回滚）

## 八、待你确认（影响最终选型）

1. **场馆是自营还是第三方合作？** 各自营 → 短期根本不需要分账
2. **比赛发起者是个人还是机构？** 个人占比高 → 必须具备对私结算能力
3. **预期月流水量级？** < 10 万 → 别上重方案；> 30 万 → 直接用服务商模式
4. **能否接受升级为有限公司？** 这是路线 A 的唯一门槛，也是长期最优解
